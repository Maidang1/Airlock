Airlock（cage-mygo）架构与核心实现深度解析

Airlock 是基于 Go + MyGo 原生桌面框架 + Objective-C cgo 构建的隔离 AI 工作台。 它用纯原生 macOS 界面取代传统重型 Electron 前端，同时完整复用成熟的 cage 隔离控制平面，统一调度 Apple Virtualization macOS 客机、Lima Linux 客机、Cloud SSH 远程 Linux/Windows 主机 以及 移动端 E2EE 中继访问。

01全局分层架构图（交互式）

点击任意架构节点查看源码路径与实现细节

系统采用清晰的双进程 + 多层隔离架构：前景层 Airlock.app（cmd/cage-desktop）负责原生渲染、系统能力与用户输入； 后台控制平面 cage（或轻量版 cage-client）独立存活于后台，管理虚拟机生命周期、代理路由、安全门控、多终端 PTY、远程网关与移动端中继。 关闭主窗口仅隐藏到 Dock，虚拟机与后台任务可继续运行。

02桌面客户端与控制平面的通信、认证与状态同步

Airlock.app 并不直接内嵌虚拟机驱动，而是通过 ControllerClient 引导、附着并与后台 cage（或 cage-client）通信。 这样即使 UI 崩溃或用户关闭窗口，隔离环境、代理核心与正在运行的 AI 任务依然稳定运行。

会话安全与多上下文路由 controller.go

  • 一次性 Ticket 换 Cookie：首次通过 cage desktop --json 获取含一次性 ticket 的 URL，随后经 POST /api/session 换取 HttpOnly 的 cage_session Cookie。
  • 统一上下文头：所有 API/WS 请求均携带 X-Cage-Connection（local 或云端 connection_id），后端 desktop_gateway.go 无缝将其路由至本地控制面或远端 SSH 隧道。
  • WKWebView 独立票据：由于 macOS WKWebView 与 Go http.CookieJar 不共享 Cookie，IssueLaunchTicket() 单独为 VNC WebView 签发一次性票据。

响应式快照状态机 store.go

  • 无锁读快照：Store 维护聚合 Snapshot（账户、初始化、VM 状态、代理、终端、Claude 账号、Tailscale、云主机、保险箱等），Snapshot() 执行浅拷贝切片保护，UI 渲染线程零阻塞读取。
  • 按需重绘：任何后端状态变更后调用 invalidate() 触发 mainWin.Invalidate() 重建 MyGo 视图树。
  • 本地偏好原子落盘：侧栏宽度、主题模式、音量等配置通过 .tmp → os.Rename 原子写入 client-preferences.json（0600）。

Agent 原生动作闭环 agent_native.go

  • CLI → 桌面窗口回调：当用户或脚本运行 cage agent 需要唤起原生能力时，控制面将任务写入 agentNativeQueue。
  • 窗口证明鉴权：AgentNativeLoop 携带 windowProof 轮询 GET /api/agent/native?consumer=window。
  • HostBridge 抽象解耦：文件选择框、保存框、Finder 定位、Touch ID 设备注册与更新触发全部封装在 HostBridge 接口，确保 headless 单测无需启动 GUI。

03三大核心交互画布的实现细节

Airlock 针对不同交互形态采用了“原生优先、按需混合”的策略：终端使用原生 libghostty-vt，macOS 客机画面使用自研二进制流 + 原生 ui.Image + 完整 CJK 输入法合成，Linux / Cloud SSH 隔离浏览器则复用轻量无铬 WKWebView + 定制 noVNC。

架构与双向 PTY 桥接 terminal_surface.go

终端直接集成 MyGo 的 plugins/terminal（底层为 Ghostty libghostty-vt 终端模拟器），通过自定义 wsTerminalConn 适配 Go io.ReadWriteCloser 与窗口尺寸同步接口。

  • 协议分层：连接 /api/terminals/{id}/stream WebSocket。后端下行的 Binary Frame 为原始 PTY 字节流（写入环形 bytes.Buffer 并通过 sync.Cond 唤醒读取器）；Text Frame 承载控制事件（如 {"type":"cli-startup","pending":true}）。
  • 输入与缩放：终端按键输入封装为 {"type":"input","data":"..."} JSON 帧；窗口变化触发 {"type":"resize","cols":C,"rows":R}。
  • HTTP/HTTPS 链接隔离打开：点击终端内链接时直接路由到隔离浏览器（对应近期提交 4bd70b5），防止误触宿主机浏览器造成泄露。

亮点特性：OAuth 链接捕获 & 拖拽上传

在客机内执行 Claude 登录时，终端输出的超长 OAuth URL 常被 PTY 折行截断并夹杂 ANSI 转义序列： 

// 1. 剥离 CSI / OSC ANSI 转义码
clean := ansiEscapeRe.ReplaceAllString(string(chunk), "")
// 2. 维护 16KB 滑动尾部缓冲并拼接硬换行
text := strings.ReplaceAll(strings.ReplaceAll(tailBuf.String(), "\r\n", ""), "\n", "")
// 3. 严格白名单域名 + /oauth/authorize 校验
//    claude.ai / claude.com / console.anthropic.com / platform.claude.com

命中后立即在顶部弹出授权引导条，一键在隔离浏览器打开完成登录。同时支持通过 MyGo transfer 拖拽宿主机文件进终端，自动上传至客机工作区并经 shellescape.Quote 转义后注入命令行。

双通道低延迟流 + 原生 ui.TextInputClient 中文输入法 macos_surface.go

当运行 Apple Silicon macOS 隔离客机 时，Airlock 不走 VNC，而是直接驱动客机内原生窗口服务（/api/macos-browser/* 或 /api/macos/claude/*），实现高 DPI Retina 画质与接近本机的中文输入体验。

控制通道 & 坐标精确映射

  • 双 WebSocket 分离：framesLoop 专注图像帧流与尺寸订阅（支持 320×240 至 2560×1600、1x/2x scale），connectionLoop 承载带请求序号（rpcSeq）的多路复用 JSON-RPC 输入事件，断线自动降级 HTTP POST .../window。
  • Letterbox 坐标换算：ComputeAspectFitRect() 保持客机窗口纵横比居中显示，MapPointNormalized() 与 MapPointPixels() 将宿主机指针坐标精确映射回客机像素空间。

原生 CJK / Dead-Key 输入法合成

  • MacOSIMETextClient 完整实现 ui.TextInputClient 接口（SetMarkedText / ReplaceText / UnmarkText / BoundsForRange）。
  • UTF-16 偏移对齐：使用 ui.UTF16Len / ui.UTF16ByteOffset 维护轻量影子缓冲（上限 512 字节），向客机发送 begin → update → commit / cancel 带单调递增 seq 的 IME 事务流，候选词框精准跟随客机光标位置。

轻量无铬 WKWebView + 定制 noVNC vnc_surface.go

面向 Lima Linux 客机与 Cloud SSH 远程主机，Airlock 仅在浏览器/桌面画布区域异步挂载一个极简 WKWebView 加载 /vnc-surface.html，其余全部 UI 保持纯 Go 原生。

  • 非阻塞异步生命周期：VNCSurfaceManager.SyncSurface() 保证在 ui.View 渲染周期内绝不阻塞，WebView 创建与配置下发均在后台 goroutine 配合 generation 代数防竞态完成。
  • Go ↔ JS 原生桥：启动时通过 mygo.BindAs("VNCBridge", vncBridge) 注入绑定对象，前端 JS 直接调用 window.mygo.call("VNCBridge.Method", ...) 上报连接状态、刷新会话票据、读写宿主机剪贴板和上传已选文件。

定制 noVNC 增强（web-surface/）

  • 动态分辨率与像素滚轮：通过 remote-display.js + cage-wheel.js 监听 DPR 与视口变化，支持高精度像素级滚轮直传 /browser/wheel。
  • 会话无 Cookie 依赖引导：URL hash 传递一次性票据，页面启动立即调用 history.replaceState 擦除地址栏票据并调用 /api/session 建立 WebView 私有会话。
  • 资产完整性校验：通过 node scripts/build-web-surface.mjs 打补丁并打包进 Go embed.FS，启动或构建时可用 cage verify-web-assets 校验哈希清单。

04音频流、双向剪贴板与 macOS Objective-C 原生层

低延迟 PCM 音频引擎 audio.go

将客机内浏览器音视频实时同步至 macOS 扬声器，严格防止音画漂移。

  • 数据规格：WebSocket /api/audio 传输 48kHz、立体声（2ch）、16-bit Little-Endian PCM。
  • 防滞后环形缓冲：PCMDecoder 内部维护 2 秒容量的 float32 环形队列，同时设置 250ms 延迟硬上限（audioMaxQueued）——超出即按立体声帧对齐（&^1）丢弃最旧样本。
  • 交互级音频会话：使用 mygo/audio 的 LatencyInteractive 策略，支持静音自动清缓冲与平滑音量调节。

双向剪贴板与防回环 clipboard_sync.go

支持文本、图片（≤ 20MB PNG）与多文件在 macOS 宿主机与客机间无缝复制粘贴。

  • changeCount 防回环：后台每 350ms 轮询 [NSPasteboard generalPasteboard].changeCount；当接收到客机剪贴板写入本机后，立即同步刷新 lastCount，彻底避免双向死循环。
  • 可靠确认与代数取消：协议包含 hello / serial / ack / release，大文件通过缓存 ID 异步拉取，并使用 generation 令牌避免过期传输覆盖新复制内容。
  • 自动缓存清理：ClipboardCacheTracker 监听粘贴板变化并自动回收不再引用的临时传输文件。

Objective-C 原生桥接 native_darwin.m

通过 cgo 直接调用 Apple Cocoa / Security / LocalAuthentication 原生框架。

  • Touch ID 钥匙串解锁：使用 kSecUseDataProtectionKeychain + kSecAccessControlBiometryCurrentSet + kSecAttrAccessibleWhenUnlockedThisDeviceOnly，确保指纹变更自动失效且绝不同步 iCloud。
  • 开发版优雅降级：检测到 errSecMissingEntitlement 时自动提示使用密码或“记住登录”，不影响开发调试。
  • 二进制 Plist 解析 & 签名验证：原生解析 Info.plist 与校验 Apple Developer ID TeamIdentifier。

05纵深安全隔离、代理治理与 Herdr 受限 MCP 桥接

Airlock 的核心价值是“让 AI Agent 在客机内全速自主执行，但对宿主机和内网保持最小暴露面”。安全策略在网络层、代理层、文件系统层、Git 层、跨宿主机 MCP 层五道防线同时生效。

防线 1：NetGuard 主机侧网络边界 internal/netguard

直接运行在 Lima hostagent 的 per-instance gvisor-tap-vsock 网络栈中，客机内即使获得 root 也无法绕过。

  • 默认“仅公网”策略：自动阻断宿主机 Loopback、私网（RFC1918）、Link-Local、以及其他 VM 的转发端口。
  • 封禁高危保留段与隧道封装：显式拦截 100.64.0.0/10（CGNAT/VPN）、198.18.0.0/15（FakeIP/Benchmark）、0.0.0.0/8、240.0.0.0/4，并拆解 NAT64 (64:ff9b::/96)、6to4 (2002::/16)、Teredo (2001::/32) 内嵌 IPv4 地址防止绕过。
  • 域名白名单与 30 分钟 DNS 记忆：配置 domain 规则后，仅放行经由内置 DNS 解析出的目标 IP（TTL 30min 支持连接池复用）。

防线 2：内置 Mihomo 托管代理核心 internal/managedproxy

客机流量可经由订阅节点、链式代理或独立出口节点出网，所有运维动作全部封装托管。

  • 严禁外部劫持：CorePath() 只加载应用内置 mihomo 可执行文件，绝不搜索 PATH 或其他应用包。
  • 变更前沙箱预检：写入配置前先在私密目录生成临时 YAML，执行 mihomo -t（15s 超时）预校验；失败则保留原配置并将日志送入诊断流。
  • 私有 UDS 控制面与错误脱敏：Mihomo 管理 API 仅监听 Unix Domain Socket（禁用 HTTP 重定向）；coreError 屏蔽 URL、路径与凭据防止日志泄露。

防线 3：挂载边界与 VCS Hook 防护 mounts + gitguard

防止客机内恶意脚本通过目录共享污染宿主机环境或植入仓库钩子实现宿主机代码执行。

  • 物理路径反逃逸校验：UnsafeLocation() 解析软链接（paths.Real）并大小写折叠（paths.Fold），严禁挂载 $HOME、agent-vm 自身、状态目录及 Lima 配置目录（及其父目录）。
  • VCS 元数据强制只读：在 SFTP 共享层对任意层级的 .git、.hg、.sl、.jj（大小写不敏感）强制只读，阻断通过改写 .git/config 或 hooks 在宿主机触发命令执行的攻击链。

防线 4：Herdr 受限宿主机 Agent MCP 桥 herdrbridge

允许客机内的 Agent 在严格约束下协作调用宿主机 CLI Agent（如 codex / claude / opencode），同时不暴露任意 Shell。

  • 隧道与令牌隔离：Host 侧监听 127.0.0.1:0 随机端口并通过 SSH 反向隧道映射到 Guest 127.0.0.1:18520；每次启动生成随机 Bearer Token 并用 subtle.ConstantTimeCompare 鉴权。
  • 标准 MCP over HTTP (2025-03-26)：暴露 POST /mcp（JSON-RPC 2.0，单条/批量）、DELETE /mcp 与 GET /health。
  • 白名单 Profile + 路径授权：仅允许配置白名单内的 Agent 与模式（区分 read_only 与 workspace-write）；所有 workdir 必须经 PathResolver 校验映射到已授权宿主机项目目录。

06Cloud SSH 远程主机与移动端零信任中继

Cloud SSH 远程工作台 internal/remotehost

同一套 Airlock 桌面端可无缝接管云端 Linux 或 Windows Server 隔离工作台，并支持发布零虚拟化依赖的 Airlock Client。

  • 显式状态机：Manager 严格管理 disconnected → connecting (ssh_connect / deploy / ...) → connected / failed，失败绝不静默切回本地或其它主机，避免误操作生产环境。
  • 透明 API 网关复用：前端视图与画布代码零分支——只需切换 X-Cage-Connection，本地 desktop_gateway.go 自动将 HTTP / WebSocket / 终端 / VNC 流量经 SSH 隧道转发给远端控制面。
  • 敏感凭据即时清零：连接协程退出时立即 clear(secrets.Passphrase) 擦除内存中的私钥口令。

移动端零信任中继 mobilelink + remotelink + relay

允许用户在手机上扫码配对、随时查看和操控本机或云端工作台，且无需暴露公网 IP。

  • 不可信中继架构：公网 cage-relay 仅充当盲转发房间（Room + 邀请码），通过 mobilelink 的 32 字节 Base64URL Capability 与 HTTPS 校验建立通道。
  • 端到端加密协议栈：internal/remotelink 在 WebSocket Binary 帧上承载完整 TLS 双向认证连接（ALPN: cage-remote/1），再于 TLS 之上运行 HTTP/2 多路复用。
  • SPKI 公钥钉扎：配对时交换 sha256:Base64(SPKI DER) 指纹；任何中间人或被攻破的 Relay 既无法读取明文，也无法伪造对端身份。单消息限 64 KiB，握手超时 15s。

07macOS 原子自更新与启动就绪回滚机制

为了杜绝“更新到一半损坏应用”或“新版本崩溃导致用户无法启动”，Airlock 将更新拆分为主应用内的 AppUpdater（internal/macnative/updater_darwin.go）与独立签名辅助进程 CageUpdateInstaller（cmd/cage-update-installer）。

防提权与防篡改检查：CageUpdateInstaller 启动后会严格验证 plan.json 所在目录属主为当前 UID 且权限掩码无 0077 暴露、校验 plan.ParentPID == os.Getppid()、比对父进程实际运行的 Bundle 路径，并用 Apple Security API 校验自身、备份包与候选包具有完全一致的 TeamIdentifier。
