H1. 双档气球全部闲置：为 macOS 客机与 MicroVM 接入驱动P1 高收益
现状：2s 探针循环（resources.go:200-306）仍在，但其钩子只对 Linux 档安装（limaembed.go:51-57）——本地 Linux 已改 MicroVM，全仓再无调用方；macOS VZ 客机与 MicroVM 都挂了气球设备却从未调节（vm_darwin_arm64.go:189-195），闲置常驻 8+ GiB。
优化：MicroVM 侧 vsock:1001 健康遥测已含内存字段（proto.go:44-53），直接驱动现成的 SetMemoryTarget/ReclaimMemory；macOS 客机采集 vm_stat + kern.memorystatus_vm_pressure_level，设安全下限 max(4 GiB, minReq)。
H2. 修复 macOS 客机启动忙等与 3s 粗粒度需求探针（MicroVM 直启天然免疫）P1 高收益
现状：macOS 客机每次启动仍走 vendored Lima：waitHostAgentStart 死循环 os.Stat 零 sleep 吃满 1 核（start.go:358-370）；waitForRequirements 串行 SSH 探针失败固定睡 3s（hostagent/requirements.go:26,61）。QEMU 5~6 次特征探测仅 Intel 安装档存在，本版休眠。
优化：加 25ms sleep；需求探针改 150ms→300ms→500ms→1s→3s 退避（热启动立省 3~9s）；MicroVM 无 hostagent/无探针，可作未来本地档性能基线。
H3. 消除多 GB 重复哈希、双次挂载与空洞全盘扫描P2 资源/时间
现状：19.77 GB IPSW 安装前被 SHA-256 扫 3 遍（~60 GB I/O）；macos.Patch 对 ASIF 挂载 2 次；copyStorageFile 校验 64 GiB 稀疏盘时把全零空洞也读完算哈希。（旧 swapBase 条目随 internal/cli 一并移除；MicroVM data.img 已用 APFS cp -c 克隆，是正确先例。）
优化：安装会话缓存 IPSW (dev,ino,size,ctime)→sha256；macos.Patch 卸卷不卸镜像直接 apfs.Chown；迁移用 SEEK_DATA/SEEK_HOLE 提速 5~10×。
H4. 跳过无变更的 Lima.Edit 与 60 个模板全量校验P2 快赢
现状：每次进程启动 WriteShare() 遍历哈希 ~60 个嵌入模板；每次 Lima.Start() 无条件跑 Edit()（抢 yq 全局锁 + 双次解析校验）。
优化：模板目录用单 manifest 标记快速跳过（仅强校验活跃 lima-guestagent.gz）；Start() 先在 Go 内存比对 CPU/RAM/TZ 字段，未变直接跳过 Edit()。

03网络数据面：用户态 Netstack、EgressGate、DNS 与代理路径

4 项 P0 级数据面瓶颈

双档本地隔离都把网络锁进进程内 gvisor-tap-vsock（macOS 客机在 hostagent usernet、MicroVM 在 internal/microvm/netstack.go 且 Forwards:{}/NAT:{}，拒绝 vzNAT），客机内不注入代理环境变量，而是经 EgressGate 强制走托管 Mihomo SOCKS5 出口。 下方视角可逐跳检视 TCP 数据面、DNS 路径（MicroVM 已是单跳直连）与 Tailnet DERP 嵌套路径。

N1. EgressGate 热路径原子无锁化 + 移出 net.InterfaceAddrs()P0 关键
现状：每笔 TCP Read/Write 抢 gate.mu；新建连接调用 3× net.InterfaceAddrs() 且 1s 看门狗也在锁内查网卡并反复重读配置 JSON。
优化：用 atomic.Uint64 (epoch) + atomic.Int64 (lease到期) 替代 gateConn.valid() 加锁；网卡表缓存 1~2s 或订阅路由变更；gate_control 先 stat mtime/size 再解析。
N2. 调大 tcp.NewForwarder maxInFlight (10 → 256+)P0 关键
现状：third_party/gvisor-tap-vsock/pkg/services/forwarder/tcp.go:23 硬编码 10，而代理握手最长 20s，高并发打开网页或 npm/apt 时极易丢 SYN 引发 1~7s 卡顿。
优化：提升至 256~512，并将拨号 context 绑定至 EgressGate epoch，受现有连接配额上限保护。
N3. 修复 ENOBUFS 忙等、每帧 SetReadDeadline 与 camLock 写锁P0 关键
现状：tap/switch.go:195 在 macOS 缓冲满时持锁 100% CPU 自旋；UDPFileConn.Read 每帧重设 deadline；rxBuf 每帧拿 camLock.Lock() 独占写锁。
优化：对齐 vz/network_darwin.go:137 加 50~100µs 退避或超预算丢包让 TCP 正常拥塞退让；删除多余 SetReadDeadline；camLock 改 RLock 快路径命中即返回。
N4. 调优 gVisor TCP 栈（SACK / 缓冲自调优 / sync.Pool）P1 高收益
现状：未开 TCPSACKEnabled 与 TCPModerateReceiveBufferOption，高 BDP 代理链路单流吞吐受限；每帧 2 次堆分配；macOS SOCK_DGRAM maxdgram=2048 限制增大 MTU。
优化：启用 SACK、缓冲自调优（默认 256KiB~1MiB、上限 4~8MiB）、CapabilityTXChecksumOffload、帧缓冲 sync.Pool 及 Windows 流 net.Buffers (writev) 合并写。

05双档显示、输入法(IME)、音频与剪贴板管线（macOS 客机 / MicroVM / 容器）

发现 2 处 P0 真实缺陷

macOS 客机走原生窗口帧流（SCStream→JPEG + AX/CGEvent 输入 + 48kHz PCM）；本地 Linux MicroVM 走按需 Xtigervnc + 宿主侧 noVNC 画布，且无音频/剪贴板/IME。旧 Lima Linux 的 Xtigervnc/IBus/PulseAudio 管线并未删除——它随容器环境（Linux 服务器）的 browserServices() 继续部署。下方视图逐跳还原三条链路的实现及热点。

D1. 立即修复 macOS 客机 IME 断链与输入并发乱序P0 真实缺陷
现状：MacOSIMETextClient 发 UUID/"ime" 被后端 32-hex 校验拒杀；sendAsync 每事件开 goroutine 乱序并洪泛 SSH。
优化：生成 32-hex session + 拉取 focusContext；改单有序队列协程并在在途期合并连续 pointer/move 与 scroll，输入 RPC 降 5~10×。
D2. 缓存 macOS 签名校验 + 帧流 2-in-flight / VideoToolbox 演进P1 高收益
现状：每帧 2× SecCodeCheckValidity、每次指针无缓存 AXIsProcessTrusted；单帧 Stop-and-Wait + 硬编码 scale=2 全帧 CPU JPEG。
优化：按 (pid, pbi_start_tvsec) 缓存验签 + 复用 AccessibilityTrust.shared；短期上 2-in-flight + 动态 DPR + 运动降质 q=0.75；中期上 SCStream → VTCompressionSession 硬编 H.264/HEVC（跳过 GPU→CPU 回读）。
D3. 容器环境 native-ime.py 4Hz xdotool 派生与 45ms 硬等（MicroVM 无 IME 不受影响）P2 快赢
现状：本地 Lima Linux 移除后，该脚本仅随容器环境（Linux 服务器）browserServices() 部署；聚焦期每 250ms 轮询仍 Popen(['xdotool','key','F24']) 并固定等待 GLib.timeout_add(45)。
优化：用已装的 python3-xlib XTEST 扩展持久发送 F24，do_process_key_event 收到后立刻回调唤醒（45ms 仅作兜底超时），延迟从 ≥45ms 降至 <2ms。
D4. 静音休眠/Opus 音频 + 原生 Go RFB 替代 WebView 画布P2 内存/电量
现状：macOS 客机 1.536 Mbps PCM 50Hz 持续发包（静音也在 flate）；MicroVM/Cloud 的 VNC 画布各驻一个 noVNC WebView（旧双 :77/:78 常驻 300~600 MB 的场景已不存在）。
优化：先落地静音暂停 + macos-audio.swift 环形缓冲与事件唤醒；中长期引入 Opus（降带宽 24~60×）及原生 Go RFB 客户端直绘 MyGo GPU 纹理。

  • 容器/云端 Linux 暖启动全量重刷（internal/cage/guest.go:315-331，经 cmd/cage/container.go:125）：每次启动仍删 components.json、跑 ~25 次独立 sudo tee 并无条件重启 4 个显示/浏览器服务——即便 manifest 修订号完全一致！本地 Linux 已不走此路径：MicroVM 镜像自含工具链，data.img 以 APFS cp -c 克隆（microvm_runtime.go:151）。
  • 优化收益：容器/云端暖启动按修订号跳过不可变文件并合单 tar 流，可削减数秒启动开销；macOS 并行安装 + cp -c + 合并 defaults import 可将冷装耗时大幅压缩。

Herdr MCP / Cloud SSH / Relay 微优化 Remote & Bridge

  • Herdr MCP（herdr_bridge.go）：VM 关闭时 keepTunnel 无退避每 2s 空轮询；herdrBridgeStatus 每次查询派 3~4 个 herdr/hc 子进程且 AutoRunner 每次重 stat 二进制路径；可改 VM 启动事件唤醒 + 缓存二进制路径。
  • Cloud SSH（remotehost/connector.go）：单连接 x/crypto/ssh 多路复用远优于本地 ControlPath=none，但缺少周期 keepalive@openssh.com（静默 NAT 断链需硬等 30s 超时），且受 Store 21 req/2.5s 的 WAN 放大影响最重。
